# 🎭 Emotion Recognition API

Локальный REST API-сервис для распознавания эмоций человека по фотографии с использованием архитектуры Vision Transformer (ViT).

Проект демонстрирует правильную слоистую архитектуру, разделение ответственности, работу с асинхронностью и интеграцию современных ML-библиотек с веб-фреймворком.

## ✨ Возможности

-  Удобная загрузка изображений через веб-интерфейс (поддержка Drag & Drop)
-  Распознавание 7 базовых эмоций: *happy, sad, angry, surprise, neutral, fear, disgust*
-  Возврат детального распределения вероятностей по всем классам
-  Оптимизированный инференс с использованием контекста `torch.no_grad()`
-  Надежная валидация входных данных (формат, размер до 5 МБ, проверка цветовых каналов)

##  Технологический стек

- **Backend:** Python, FastAPI, Pydantic, Uvicorn
- **Machine Learning:** PyTorch, Hugging Face `transformers`
- **Модель:** [trpakov/vit-face-expression](https://huggingface.co/trpakov/vit-face-expression) (Vision Transformer, ~400 MB)
- **Frontend:** HTML5, CSS3, Vanilla JavaScript (минималистичный дизайн, без тяжелых фреймворков)
- **Обработка данных:** Pillow (PIL), NumPy

##  Архитектура проекта

Проект построен по принципам **слоистой архитектуры (Layered Architecture)**, что обеспечивает чистоту кода, тестируемость и легкость поддержки:

1. **Router Layer** (`app/routers/`): Обработка HTTP-запросов, валидация `multipart/form-data`, маппинг исключений в HTTP-статусы (400, 500).
2. **Service Layer** (`app/services/`): Бизнес-логика. Оркестрация пайплайна: валидация байтов → препроцессинг → инференс модели → постпроцессинг.
3. **Model Layer**: Инкапсуляция загрузки и вызова ML-модели. Использование `lifespan` в FastAPI для загрузки модели в оперативную память ровно один раз при старте сервера.

## 🛠️ Локальный запуск

### 1. Подготовка окружения

```bash
# Перейдите в папку проекта
cd emotion-recognition-api

# Создайте виртуальное окружение
python -m venv venv
```

Активируйте окружение:

```bash
# Windows
venv\Scripts\activate

# macOS / Linux
source venv/bin/activate
```

### 2. Установка зависимостей

```bash
pip install -r requirements.txt
```

> **Примечание:** при первом запуске библиотека `transformers` автоматически скачает веса модели (~400 МБ) из Hugging Face Hub и закэширует их локально. Повторные запуски пройдут мгновенно.

### 3. Запуск сервера

```bash
uvicorn app.main:app --reload --port 8000
```

В консоли вы увидите сообщения о загрузке приложения и модели


### 4. Использование

| Интерфейс | Адрес |

| Веб-интерфейс | [http://localhost:8000](http://localhost:8000) |

## 📡 API Endpoints

| Метод | Путь | Описание |
| :--- | :--- | :--- |
| `POST` | `/api/v1/predict/emotion` | Распознавание эмоции. Принимает `multipart/form-data` с полем `file` (JPEG/PNG, до 5 МБ) |
| `GET` | `/health` | Статус сервиса и флаг загруженности модели |
| `GET` | `/docs` | Интерактивная документация Swagger UI |
| `GET` | `/redoc` | Документация ReDoc |

### Пример запроса

```bash
curl -X POST "http://localhost:8000/api/v1/predict/emotion" \
     -H "accept: application/json" \
     -F "file=@photo.jpg"
```

### Пример ответа

```json
{
  "status": "success",
  "predicted_emotion": "happy",
  "confidence": 0.92,
  "all_probabilities": {
    "happy": 0.92,
    "surprise": 0.04,
    "neutral": 0.02,
    "sad": 0.01,
    "angry": 0.005,
    "fear": 0.003,
    "disgust": 0.002
  },
  "processing_time_ms": 145.3
}
```

### Коды ошибок

| Статус | Причина |
| :--- | :--- |
| `400 Bad Request` | Неподдерживаемый формат файла, превышение размера 5 МБ, повреждённое изображение |
| `500 Internal Server Error` | Модель не загружена или сбой во время инференса |

## ⚠️ Важные примечания

- **Холодный старт.** При первом запросе после запуска сервера модель инициализируется в памяти (10–30 секунд в зависимости от оборудования). Все последующие запросы выполняются за ~100–300 мс.
- **Устойчивость к форматам.** Сервис автоматически конвертирует входные изображения (включая grayscale `L` и прозрачные `RGBA`) в формат `RGB`, ожидаемый моделью. Это предотвращает ошибки размерности тензоров на этапе предобработки.
- **Безопасность.** Размер загружаемого файла жёстко ограничен 5 МБ на уровне роутера — это защищает от переполнения памяти при обработке тяжёлых изображений.
- **Отсутствие блокировок event loop.** Загрузка модели выполняется в `lifespan` до начала приёма запросов, а тяжёлый инференс не мешает обработке других подключений.
